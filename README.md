# Attribute interference in text-to-image prompts

Project P40. When one more constraint is added to a prompt, which of the constraints already in it stop being satisfied?

We compare SD 1.5 (baseline) and SDXL on 576 factorial prompts with 4 seeds each, 2,304 images per model. Prompts vary color, count, position, material and a second object. All models are pretrained and nothing is trained.

## Main results

| Metric | SD 1.5 | SDXL |
|---|---:|---:|
| Strict accuracy | 18.4% | 28.0% |
| Color | 48.4% | 65.4% |
| Material | 37.7% | 61.8% |
| Second object | 37.3% | 64.1% |
| Count | 22.2% | 19.0% |
| Position | 19.7% | 22.2% |
| Generation time on Tesla T4 | 6.6 s per image | 33.1 s per image |

SDXL is better overall. Neither model handles count or position well. Adding a second object lowers color accuracy by 27 points for SD 1.5 and 33 points for SDXL.

Labels come from Qwen2.5-VL in 8-bit and OWLv2 (confidence 0.2, NMS IoU 0.5). They are checked against 150 human-labeled SDXL images. Tables are in `results/`.

## Reproduce the analysis

These steps need no GPU. Download both runs and set their paths:

```bash
SD15=path/to/main_sd15
SDXL=path/to/main_sdxl

python scripts/evaluator_agreement.py --annotations notebooks/review/annotations_test150.csv --run "$SDXL" \
  --first-annotator notebooks/review/annotations_anna.csv --second-annotator notebooks/review/annotations_saida.csv \
  --output results/evaluator_agreement
python scripts/evaluator_dependence.py --base "$SD15" --second "$SDXL" --output results/evaluator_dependence
python scripts/owl_threshold_sensitivity.py --base "$SD15" --second "$SDXL" --output results/owl_threshold_sensitivity
python scripts/interaction_analysis.py --base "$SD15" --second "$SDXL" --output results/interaction_analysis
python scripts/select_failure_candidates.py --base "$SD15" --second "$SDXL" \
  --annotations results/evaluator_agreement/annotations_clean.csv --output results/failure_candidates
```

| Output | Content |
|---|---|
| `results/evaluator_agreement` | Agreement with human labels, kappa, count errors, inter-annotator agreement |
| `results/evaluator_dependence` | Qwen and OWLv2 compared for count and position |
| `results/owl_threshold_sensitivity` | Results at OWLv2 thresholds 0.2, 0.25 and 0.3 |
| `results/interaction_analysis` | Non-additivity ratios and mixed logistic regression |
| `results/failure_candidates` | Failure analysis candidates |
| `results/report_figures` | Failure cases figure |

## Run generation and evaluation

The final runs were executed in Colab and on a VM with these notebooks:

| Notebook | Purpose |
|---|---|
| `notebooks/sd15_baseline_generation_evaluation.ipynb` | SD 1.5 generation and evaluation |
| `notebooks/sdxl_generation_evaluation.ipynb` | SDXL smoke test, pilot, generation and evaluation |
| `notebooks/sdxl_pilot_freeze_owl_calibration.ipynb` | Evaluator freeze and OWLv2 calibration |
| `notebooks/qwen_yes_bias_control_questions.ipynb` | Qwen control questions on SD 1.5 |

The pipeline is also available from the command line, with configs in `configs/`:

```bash
attribute-interference prepare --config configs/smoke.yaml --output outputs/smoke
attribute-interference generate --config configs/smoke.yaml --output outputs/smoke
attribute-interference evaluate --config configs/smoke.yaml --output outputs/smoke
attribute-interference analyze --config configs/smoke.yaml --output outputs/smoke
```

The configs use Qwen in NF4. Our final labels use 8-bit Qwen from the notebooks, stored in `qwen_int8_records`.
